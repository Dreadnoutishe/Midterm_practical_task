# Space Bounty Hunters API

Midterm practical assignment built with **FastAPI, PostgreSQL, and SQLAlchemy**.
The API stores wanted criminals and a journal of capture attempts. No frontend is required.

## Quick start (recommended)

Install Docker Desktop and start it. Extract this archive, open a terminal inside
`space-bounty-hunters`, and run:

```bash
docker compose up --build
```

Wait for `Application startup complete`, then open:

- Swagger UI: http://localhost:8000/docs
- Criminals: http://localhost:8000/api/criminals/
- Hunt logs: http://localhost:8000/api/hunts/

The first startup creates the tables and inserts **5 criminals and 10 hunt logs**.
PostgreSQL data is saved in the `postgres_data` Docker volume. Later starts preserve
changes and do not recreate deleted hunt logs. Sample credentials are `bounty` /
`bounty`; database name: `bounty_hunters`.

Stop with Ctrl+C, then `docker compose down`. To deliberately erase all local demo
data and start fresh, run `docker compose down -v`, then `docker compose up --build`.
If ports 5432 or 8000 are already in use, stop the conflicting local service or
change the left side of the corresponding port mapping in `compose.yaml`.

## API endpoints

| Method | URL | Purpose | Success |
|---|---|---|---|
| GET | `/api/criminals/` | List, filter, and sort criminals | 200 |
| GET | `/api/criminals/{id}/` | Criminal details | 200 |
| GET | `/api/hunts/` | List logs; optional `criminal_id` filter | 200 |
| GET | `/api/hunts/{id}/` | Hunt details | 200 |
| POST | `/api/hunts/` | Create a hunt log | 201 |
| PATCH | `/api/hunts/{id}/` | Update success and/or notes | 200 |
| DELETE | `/api/hunts/{id}/` | Delete a hunt log | 204 |

Criminal filters: `min_reward`, `max_reward`, `armed`, `has_crew`, and
`escape_master`. All supplied filters apply together. Reward boundaries are
inclusive. Boolean filters support `true` and `false`. Sorting accepts `reward`
(ascending) and `-reward` (descending), with ID breaking ties. Default order is ID.

Example with all filters:

```text
http://localhost:8000/api/criminals/?min_reward=5000&max_reward=20000&armed=true&has_crew=false&escape_master=true&sort=-reward
```

The seeded matching criminal is Night Falcon. Filter logs with:

```text
http://localhost:8000/api/hunts/?criminal_id=5
```

POST example:

```json
{
  "criminal_id": 3,
  "success": false,
  "notes": "Target escaped through an asteroid field."
}
```

PATCH example (send only the field being changed):

```json
{
  "success": true
}
```

`criminal_id` must reference an existing criminal. Missing records return 404;
invalid IDs, bodies, query values, or reward ranges return 422. `success` in JSON
must be a real boolean, not a string. PATCH accepts only `success` and `notes`,
requires at least one field, and rejects null values. Notes can be empty and are
limited to 10,000 characters. `created_at` is generated by PostgreSQL; client
attempts to set it are rejected. PATCH preserves it. A list filter with no
matches returns `[]`.

Rewards use `NUMERIC(14,2)` to preserve monetary precision. JSON serializes reward
as a decimal string (for example `"15000.00"`). Convert it to a number for client
sorting. Timestamps include a timezone.

## Models and relationship

`WantedCriminal`: id, optional name, nickname, reward, last_known_location,
difficulty (1-10), armed, has_crew, escape_master. The assignment permits a text
location; this implementation uses `last_known_location` for a descriptive note.

`HuntLog`: id, criminal_id, success, notes, created_at.

One criminal has multiple hunt logs. `HuntLog.criminal_id` is an indexed foreign
key to `WantedCriminal.id`; the ORM relationship is defined in both directions.
Database constraints enforce a nonnegative reward and difficulty from 1 to 10.

## Postman

1. Start the application.
2. In Postman, select **Import** and open
   `postman/Space_Bounty_Hunters.postman_collection.json`.
3. The collection variable `base_url` defaults to `http://localhost:8000`.
4. Open the collection runner and run all requests in their existing order.

The collection includes criminal listing/details, all filters combined, both
sort directions, hunt listing/filtering, complete hunt CRUD, and invalid
requests. Tests check status codes, filtering, sorting, partial updates, and the
server timestamp. The create request saves its ID into `hunt_id`; later requests
use and finally delete that record. Use a freshly seeded database if sample
records have been manually changed. Expected 404 and 422 responses are successful
negative tests, not collection failures.

## Run locally without Docker

Requires Python 3.12 and a running PostgreSQL 16 server. In a PostgreSQL admin
terminal, create the role and database (run CREATE DATABASE outside a transaction):

```sql
CREATE USER bounty WITH PASSWORD 'bounty';
CREATE DATABASE bounty_hunters OWNER bounty;
```

Create and activate a virtual environment from the project directory:

```bash
python -m venv .venv
```

Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
Copy-Item .env.example .env
```

Linux/macOS:

```bash
source .venv/bin/activate
cp .env.example .env
```

Edit `.env` if your PostgreSQL username, password, port, or database differs.
Then run:

```bash
python -m pip install -r requirements.txt
python -m app.seed
python -m uvicorn app.main:app --reload
```

The seed command creates the tables and initial data when the criminals table
is empty. Once sample criminals exist, it leaves existing data unchanged. Run
one seed process at a time. The API itself expects the database setup to have
completed before it starts.

## SQL import alternative

`database/init.sql` contains the matching PostgreSQL schema, constraints, index,
5 criminals, 10 logs, and sequence resets. Import it into an **empty** database
instead of using `python -m app.seed`:

```bash
psql -h localhost -U bounty -d bounty_hunters -v ON_ERROR_STOP=1 -f database/init.sql
```

Enter the demo password `bounty` when prompted. In pgAdmin, connect as `bounty`,
select the empty database, open Query Tool, load `database/init.sql`, and execute
it. Start Uvicorn after import. Do not import over an already initialized schema.
Both the SQL import and Python seed produce the same sample records. The SQL
file is a plain-text SQL script, not a pgAdmin custom-format backup.

## Automated tests

Tests use PostgreSQL, with each test's writes rolled back. Use a separate test
database. With the Docker database running, create it once:

```bash
docker compose exec db createdb -U bounty bounty_hunters_test
python -m pip install -r requirements-dev.txt
```

Windows PowerShell:

```powershell
$env:DATABASE_URL = "postgresql+psycopg://bounty:bounty@localhost:5432/bounty_hunters_test"
python -m app.seed
python -m pytest -q
Remove-Item Env:DATABASE_URL
```

Linux/macOS:

```bash
export DATABASE_URL=postgresql+psycopg://bounty:bounty@localhost:5432/bounty_hunters_test
python -m app.seed
python -m pytest -q
unset DATABASE_URL
```

The test suite covers the endpoint lifecycle, filters/sorting, invalid inputs,
foreign-key checks, and timestamp protection. Use the included development
requirements so the test client is available.

## Project files

- `app/main.py`: routes, filters, and HTTP responses.
- `app/models.py`: SQLAlchemy tables and relationship.
- `app/schemas.py`: request validation and response schemas.
- `app/database.py`: environment configuration and database sessions.
- `app/seed.py` and `database/seed.json`: repeatable initial setup.
- `database/init.sql`: standalone schema and data import.
- `postman/`: importable Postman collection with assertions.
- `tests/`: PostgreSQL integration tests.
- `Dockerfile` and `compose.yaml`: application and PostgreSQL startup.
